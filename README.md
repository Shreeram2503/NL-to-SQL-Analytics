# Ask Your Database — Natural Language to SQL Analytics Assistant

Type a question in plain English ("what are the top 5 products by revenue?")
and get back a real SQL query, a results table, and an auto-generated chart -
no SQL knowledge required to use it.

**\[Live demo link - https://nl-2-sql-assistant.streamlit.app/]**

## Why this project
Most entry-level data portfolios show static dashboards or one-off EDA
notebooks. This is a small working *application*: it takes live user input,
calls an LLM to generate SQL, validates that SQL is safe, executes it
against a real database, and renders the result - end to end, deployed,
clickable.

## Architecture

```
User question (Streamlit)
        |
        v
Claude API (schema + question -> SQL)
        |
        v
Safety check (SELECT-only, single statement)
        |
        v
SQLite database (executes the query)
        |
        v
Results table (pandas) -> auto chart (if the shape fits)
```

## Tech stack
* **Python** - core language
* **Streamlit** - web UI, no frontend code needed
* **Anthropic Claude API** - natural language to SQL translation
* **SQLite** - lightweight embedded database (retail dataset, generated
synthetically - see `build\\\_db.py`)
* **Pandas** - results handling and chart data shaping

## Database schema

Four tables: `customers`, `products`, `orders`, `order\\\_items` - a standard
normalized retail schema. See `nl\\\_to\\\_sql.py` for the full column list.

## Example questions section:
- What are the top 5 products by total quantity sold?
- Which city has the most customers?
- What is the total revenue by product category?
- Show me the five most recent orders
- Tell me about the business (correctly refused: too vague for SQL)

## Key design decisions:
- LLM output is untrusted. Every generated query passes is_safe_select(): single statement, must start with SELECT, data-modifying keywords blocked.
  Only then does it run
- Logic and UI are seperate: nl_to_sql.py (schema, prompt, safety, execution) and app.py (Streamlit UI only)
- The model is given the exact schema and must answer No_QUERY_POSSIBLE when a queston cannot be answered, so it refuses instead of inventing columns.
- The database is generated by build_db.py and built at startup if missing, so the repo stays small and anyone can run it.
- Charts are drawn only when the result shape fits (one label column, one numeric column, 25 rows or fewer).

## Challenges and fixes

- Model response parsing: newer models can return a thinking block before the text block, so response.content\[0].text crashed. Fixed by selecting the block whose type is text.
- Hosting: the deployed filesystem is read-only, so the SQLite file is created in the system temp directory.
- Startup race: the database check only tested whether the file existed, so an empty file skipped the build and queries failed with "no such table". Fixed by checking that the customers table exists and building the database once per server process.
- Secrets: the API key lives in a local .env file and in Streamlit Cloud secrets, never in the repo.
- Startup race on the hosted app: the database check only tested whether the file existed, so an empty leftover file skipped the build and queries failed with "no such table". Fixed by checking that the customers table exists and building the database once per server process.

##Limitations and roadmap:
- The keyword blocklist is defense in depth, next step is opening SQLite in read-only mode.
- No query history.
- single-turn only: no follow-up questions.
- Planned: automatic retry that feeds SQL errors back to the model, pytest tests for the safety check, postgres support.

## Setup

```bash
# 1. Clone and enter the project
git clone <your-repo-url>
cd nl2sql\\\_project

# 2. Install dependencies
pip install -r requirements.txt

# 3. Build the database (creates retail.db)
python build\\\_db.py

# 4. Add your API key
cp .env.example .env
# then edit .env and paste your key from https://console.anthropic.com

# 5. Run the app
streamlit run app.py
```

The app will open at `http://localhost:8501`.

## Deploying (free)

1. Push this repo to GitHub (make sure `.env` is *not* included — check
`.gitignore`)
2. Go to [share.streamlit.io](https://share.streamlit.io), connect your
GitHub repo
3. In the app's "Secrets" settings, add:

```
   ANTHROPIC\\\_API\\\_KEY = "your-key-here"
   ```

4. Deploy — you'll get a public URL to put on your resume and LinkedIn
